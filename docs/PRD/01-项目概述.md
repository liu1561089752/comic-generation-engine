# 第一篇 项目概述

---

## 第1章 项目简介

### 1.1 项目名称

**AI Webtoon Factory（AI韩漫工厂）**

### 1.2 项目背景

随着 Webtoon（韩漫）在全球市场的快速增长（2025年全球规模已超百亿美元），市场对高质量 Webtoon 内容的需求持续攀升。然而，传统 Webtoon 制作流程依赖大量人工：

- 编剧撰写脚本
- 分镜师绘制分镜
- 主笔绘制线稿
- 上色师完成上色
- 后期编辑添加气泡和特效

一部商业 Webtoon 通常需要 10-20 人的团队，制作周期为数周至数月。

AI 生图技术（Stable Diffusion、Midjourney 等）的快速发展使得单人完成漫画成为可能，但现有 AI 漫画工具普遍存在以下问题：

1. **角色不一致**：同一人物在不同画格中相貌、服装、体型变化
2. **缺乏工业化流程**：工具只是"生图工具"，而非"制作系统"
3. **数据难以追溯**：Prompt 一次性使用，无法复用和管理
4. **缺乏质量控制**：没有一致性检测、漏字检测等 QA 流程

**AI Webtoon Factory** 的目标是填平这一鸿沟——将韩漫工作室的工业化流程全部 AI 化，打造一套从小说到可发布 Webtoon 的完整生产线。

### 1.3 项目愿景

> **让一个人拥有一个韩漫工作室的生产力。**

通过 AI 辅助的工业化管线，使创作者能够独立完成剧本导入、角色设计、分镜规划、批量生图、质量控制和最终导出，生产出达到商业发布标准的 Webtoon。

### 1.4 项目范围

**覆盖范围：**

- 从 TXT/DOCX/Markdown 小说导入到 Webtoon 导出的全流程
- 支持现代、古代、未来、校园、都市、玄幻、修仙等主流 Webtoon 题材
- 支持 1:1.34（1080×1440+）标准 Webtoon 比例
- 支持 PNG/JPG/PSD/ZIP/长图等多种导出格式

**不覆盖范围：**

- 不提供 AI 写小说功能（需外部导入）
- 不提供在线发布平台（仅导出）
- 不提供协同编辑（单用户模式 V1）

## 第2章 产品定位

### 2.1 产品类型

B2C 桌面端 Web 应用（Python FastAPI 后端 + React/TypeScript 前端），面向个人的 AI 辅助 Webtoon 制作系统。

### 2.2 核心差异化

| 维度 | 现有 AI 漫画工具 | AI Webtoon Factory |
|------|-----------------|-------------------|
| 流程 | 输入 Prompt → 出图 | 小说导入 → 14道工业工序 → 导出 |
| 角色管理 | 无 | 人物IP中心（六视图+Scale+Relation） |
| 数据核心 | 自然语言 Prompt | 结构化数据库对象（Novel→Chapter→Scene→Panel→Shot→Bubble→Prompt→Image） |
| 一致性 | 靠 Prompt 硬写 | AI 自动化一致性检测 |
| 可追溯 | 无 | 每张图关联原文段落 |
| 可迭代 | 重跑全部 | 单 Panel 独立重新生成 |

### 2.3 目标用户

| 用户类型 | 描述 | 核心需求 |
|---------|------|---------|
| 独立漫画创作者 | 单人制作 Webtoon 的作者 | 提效、保证质量 |
| 小说作者 | 想将自己的小说改编为 Webtoon | 低门槛改编 |
| AI 艺术创作者 | 探索 AI 漫画可能性的创作者 | 工业化流程 |
| 小型漫画工作室 | 2-5 人的微型团队 | 批量生产、质量控制 |

## 第3章 产品目标

### 3.1 业务目标

1. **MVP 阶段**：实现完整的单部短篇小说 → Webtoon 制作管线，可产出 20-50 话的完整 Webtoon
2. **V2 阶段**：支持多项目并行、批量生图、一致性检测，支持中长篇（50-200 话）
3. **V3 阶段**：支持插件系统、第三方模型接入、商业化发布

### 3.2 质量目标

- **角色一致性**：同一角色在整部漫画中服饰、发型、五官一致性 > 95%
- **场景一致性**：同一场景在不同话中保持一致
- **画风一致性**：整部漫画画风统一，无明显跳变
- **生产速度**：单个 Panel 从 Prompt 到候选图平均 < 30 秒
- **操作流畅度**：前端页面切换 < 1 秒，画廊滚动 60fps

### 3.3 约束

- 后端：Python 3.11+ (FastAPI)
- 数据库：PostgreSQL 15+（开发可用 SQLite 替代）
- AI 模型：支持 OpenAI API 兼容格式的 LLM + Stable Diffusion API 兼容格式的生图模型
- 前端：React 18+ / Vue 3+ + TypeScript
- 部署：Docker 容器化

## 第4章 设计原则

### 4.1 结构化优先

> **所有数据以结构化格式存储，而非自然语言。**

- 一个 Prompt 不再是字符串，而是一个包含 Character、Environment、Action、Camera 等 10 层属性的 JSON 对象
- 一个 Panel 不是一个图片 + Prompt，而是一个关联了 Scene、Characters、Bubble、Shot、Layout 等对象的数据库记录
- 所有 AI Agent 输入结构化 JSON，输出结构化 JSON

### 4.2 可追溯

> **每个 Panel 都可追溯到原文。**

- 每张图片关联原文段落（Novel → Chapter → Scene → Panel）
- 支持"点击画格 → 查看原文"的正反追溯
- 图片版本历史完整记录

### 4.3 可迭代

> **任何时候都可以单独重新生成任意元素。**

- 可以单独重新生成某个 Panel 的图片，不影响其他
- 可以重新调整分镜策略，只影响后续 Panel
- 可以更换角色服装，自动更新涉及的所有 Panel

### 4.4 工业化

> **像工厂流水线一样可重复、可控制、可量化。**

- 每个环节都有明确的输入/输出定义
- 每个环节都支持人工审核和干预
- 每个环节都有质量门禁

### 4.5 模块化

> **每个模块独立可替换。**

- AI Agent 可单独升级或替换（如从 GPT-4 换到 DeepSeek）
- 生图模型可切换（如从 SDXL 换到豆包/通义万相）
- 模板可复用和共享

## 第5章 用户角色

### 5.1 创作者（Creator）

**主要角色**，使用系统制作 Webtoon 的用户。

**权限：**
- 项目管理（CRUD）
- 小说导入与管理
- 世界观与角色设定
- 分镜与版式规划
- Prompt 编辑与测试
- 生图任务管理
- 图片选择与审核
- 漫画编辑与导出

### 5.2 审核员（Reviewer）

**辅助角色**，负责质量检查。

**权限：**
- 查看所有面板
- 一致性检测报告查看
- 质量评分查看
- 标注问题面板
- 打回重新生成

### 5.3 管理员（Admin）

**系统管理角色**。

**权限：**
- 用户管理
- 系统设置
- 模型配置
- 存储管理
- 操作日志查看

## 第6章 业务流程总览

### 6.1 核心生产流程

```
Novel（小说导入）
    │
    ▼
Preprocessing（清洗/章节拆分/段落编号）
    │
    ▼
World Building（世界观设定）
    │
    ▼
Character IP（角色设计/六视图/Scale Sheet/Relation Sheet）
    │
    ▼
Story Analysis（剧情分析 → Scene 提取）
    │
    ▼
Semantic Split（语义切句 → Panel 切分）
    │
    ▼
Storyboard（分镜规划 → 镜头/景别/运镜）
    │
    ▼
Layout（版式规划 → 单格/双格/三格/整页）
    │
    ▼
Bubble Planning（气泡规划 → 对白/旁白/内心）
    │
    ▼
Prompt Generation（10 层 Prompt 组装）
    │
    ▼
AI Image Generation（批量生图 → 候选图）
    │
    ▼
Consistency Check（一致性检测 → AI 质量评分）
    │
    ▼
Human Review（人工审核 → 选择/修改）
    │
    ▼
Comic Editor（漫画编辑 → 最终排版）
    │
    ▼
Export（导出 PNG/JPG/PSD/ZIP/长图）
```

### 6.2 数据层级

```
Novel（小说）
  ├── Chapter（章节）
  │     ├── Scene（场景）
  │     │     ├── Panel（画格）
  │     │     │     ├── Shot（镜头）
  │     │     │     ├── Bubble（气泡）
  │     │     │     │     ├── Narration（旁白）
  │     │     │     │     ├── Dialogue（对白）
  │     │     │     │     └── Thinking（内心）
  │     │     │     ├── Prompt（多个版本）
  │     │     │     └── Image（多个候选 → 选中）
  │     │     └── ...
  │     └── ...
  └── ...
```
