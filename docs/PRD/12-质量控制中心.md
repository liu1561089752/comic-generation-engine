# 第十二篇 质量控制中心

---

## 第77章 人物一致性检测

### 77.1 功能概述

人物一致性检测模块利用 AI 视觉分析技术，自动检测新生成图片中角色外观特征与人物 IP 中心设定值的一致性。系统逐项比对发色、发型、瞳色、肤色、服装等关键特征维度，对不一致项进行高亮标记，并给出检测通过/不通过的判定结论。该模块是确保漫画中同一角色在不同画面中保持视觉统一的核心质量门禁。

**输入：**
- 新生成的 Panel 图片
- 图片中出现的角色 ID 列表
- 人物 IP 中心的角色特征设定值

**输出：**
- 各特征维度的一致性检测结果
- 不一致项的高亮标注
- 检测通过/不通过判定

### 77.2 功能点

#### 77.2.1 AI 检测新生成图片中角色特征

**功能描述：**
- 对每张新生成的图片调用 AI 视觉检测模型
- 自动识别图片中出现的所有角色（人脸检测 + 角色匹配）
- 对每个识别到的角色提取以下特征：
  - 发色（检测头发区域的 dominant color）
  - 发型（分类：直发/卷发/马尾/短发等）
  - 瞳色（检测瞳孔区域颜色）
  - 肤色（检测面部/手部皮肤颜色）
  - 服装（检测着装类型和颜色）
- 检测结果附带置信度评分（0-100%）

**操作流程：**
1. 图片生成完成后，系统自动触发人物一致性检测
2. 检测引擎在后台执行视觉分析
3. 识别图片中的角色面部区域
4. 与项目中的已知角色库进行人脸匹配
5. 对匹配到的角色提取各维度特征值
6. 检测完成后自动生成检测报告

**界面要求：**
- 检测过程在后台进行，用户无感
- 检测中的 Panel 显示"检测中..."状态标记
- 检测完成后自动更新检测结果状态
- 检测失败（如未检测到人脸）时显示"无法检测"提示

#### 77.2.2 与人物 IP 中心设定的特征值对比

**功能描述：**
- 将 AI 检测到的特征值与人物 IP 中心的设定值逐一比对
- 比对维度与人物设定（第 31 章）保持一致
- 每个维度的比对结果分为三种状态：
  - 一致（检测值与设定值匹配）
  - 不一致（检测值与设定值不匹配）
  - 无法确定（检测置信度过低或未检测到该特征）
- 一致的维度显示绿色通过，不一致显示红色报警

**比对维度：**

| 特征维度 | 设定值（示例） | 检测值（示例） | 比对结果 |
|---------|--------------|--------------|---------|
| 发色 | 金色 (#FFD700) | 金色 (#F5D000) | ✓ 一致 |
| 发型 | 及腰直发 | 及腰直发 | ✓ 一致 |
| 瞳色 | 红色 (#FF0000) | 棕色 (#8B4513) | ✗ 不一致 |
| 肤色 | 白皙 (#FFF5E6) | 白皙 (#FFF0E0) | ✓ 一致 |
| 服装 | 天玄学院校服 | 天玄学院校服 | ✓ 一致 |

**操作流程：**
1. AI 检测完成后，系统自动提取各维度检测值
2. 从人物 IP 中心读取该角色的特征设定值
3. 逐维度计算检测值与设定值的差异
4. 颜色类特征：计算色差 ΔE（以 ΔE < 10 为一致阈值）
5. 类别类特征（发型、服装等）：计算分类匹配度
6. 生成每个维度的比对结论

**界面要求：**
- 比对结果以列表形式展示
- 每行一个比对维度，显示：维度名称 + 设定值 + 箭头 + 检测值 + 状态图标
- 一致项：绿色 ✓ + 绿色背景行
- 不一致项：红色 ✗ + 红色背景行 + 高亮差异值
- 无法确定项：灰色 ❓ + 灰色背景行
- 设定值中颜色类特征显示对应色块

#### 77.2.3 不一致项高亮标记

**功能描述：**
- 对检测结果中不一致的特征维度进行突出展示
- 不一致项在报告中以红色高亮显示
- 高亮内容包含：设定值（绿色文字）与检测值（红色文字）的对比
- 同时在原图上用热力图或边界框标注不一致的区域
- 支持点击不一致项查看图片上对应的检测区域

**操作流程：**
1. 在检测报告中找到标记为不一致的维度
2. 该维度行整体红色高亮
3. 显示格式如："发色：设定 黑色 → 检测 棕色"
4. 点击不一致项，原图上弹出检测区域标注
5. 标注以半透明色块覆盖在图片对应区域
6. 可手动关闭标注或清除高亮

**界面要求：**
- 不一致项高亮行：红色左侧边框 + 红色底色（浅红）
- 对比内容格式：设定值显示为绿色，检测值显示为红色
- 数值差异：颜色差异显示 ΔE 值和色块对比
- 图片标注：在图片上以半透明色块框出检测区域
- 检测区域标注颜色：与特征维度颜色对应（发色=金色框、瞳色=红色框等）
- 点击标注区域弹出详细信息的 tooltip
- 批量标注切换：在图片上显示/隐藏所有检测区域标注

#### 77.2.4 检测通过/不通过判定

**功能描述：**
- 根据不一致项的数量和严重程度生成综合判定结论
- 判定标准：
  - 通过：0 项不一致，或仅 1 项轻微不一致（色差 ΔE 10-15）
  - 有条件通过：1-2 项不一致，但均为非关键特征
  - 不通过：3 项及以上不一致，或涉及关键特征（发色、瞳色）
- 判定结果影响：不通过的 Panel 自动标记为"需重新生成"
- 判定结果记录在 Panel 的质量状态中

**操作流程：**
1. 所有维度比对完成后，系统自动计算综合判定
2. 根据不一致数量和严重程度判定通过/有条件通过/不通过
3. 判定结果显示在检测报告顶部
4. 不通过的 Panel 在任务列表中标记为"质量不通过"
5. 不通过的 Panel 自动进入"需重新生成"队列
6. 用户可手动覆盖判定结果（标记为"人工通过"）

**界面要求：**
- 判定结果徽章：检测报告顶部的大号徽章
  - 通过：绿色 ✓ 通过
  - 有条件通过：黄色 ⚠️ 有条件通过
  - 不通过：红色 ✗ 不通过
- 判定详情：徽章下方显示"X 项一致 / Y 项不一致 / Z 项无法确定"
- 手动覆盖按钮：判定结果旁的"标记为通过"或"提交审核"按钮
- 覆盖记录：手动覆盖操作记录到操作日志
- 不通过面板标记：在 Panel 缩略图上显示红色"QC 不通过"角标
- 自动重生成入口：不通过判定旁的"重新生成"快捷按钮

### 77.3 数据模型

| 字段 | 类型 | 说明 |
|------|------|------|
| detection_id | UUID | 检测记录唯一标识 |
| panel_id | UUID | 关联 Panel ID |
| image_id | UUID | 关联图片 ID |
| character_id | UUID | 检测的角色 ID |
| character_name | String | 角色名称（冗余） |
| detected_features | JSON | 检测到的特征值 |
| expected_features | JSON | 期望的特征值（来自人物设定） |
| comparison_results | JSON | 各维度比对结果 |
| overall_verdict | Enum | passed / conditional / failed |
| confidence_scores | JSON | 各维度检测置信度 |
| highlighted_regions | JSON | 不一致区域的图片标注坐标 |
| is_manually_overridden | Boolean | 是否被人工覆盖判定 |
| created_at | DateTime | 检测时间 |

## 第78章 场景一致性检测

### 78.1 功能概述

场景一致性检测模块自动分析新生成图片中的场景元素，与世界观设定库中的场景定义进行一致性比对。系统检测建筑风格、季节特征、天气状况等维度是否与预期设定一致，当出现季节不符、天气矛盾等明显不一致时触发报警。该模块确保漫画中的场景视觉呈现与世界观设定保持统一。

**输入：**
- 新生成的 Panel 图片
- 该 Panel 关联的场景设定 ID（来自世界观资产库）

**输出：**
- 场景元素检测结果
- 与设定值的一致性比对报告
- 不一致报警

### 78.2 功能点

#### 78.2.1 检测场景元素与世界观设定的一致性

**功能描述：**
- AI 视觉分析图片中的场景相关元素
- 检测维度包括：
  - 建筑风格：现代/古典/未来/奇幻/中式/欧式等
  - 环境类型：室内/室外/城市/自然/地下等
  - 季节特征：春/夏/秋/冬（植被状态、色彩倾向）
  - 天气状况：晴天/阴天/雨天/雪天/雾天等
  - 时间标识：白天/黄昏/夜晚/黎明
  - 氛围色调：明亮/昏暗/阴郁/温暖
- 从世界观资产库读取该场景的设定值进行比对

**操作流程：**
1. 人物一致性检测完成后自动触发场景检测
2. 也可在控制中心手动触发场景检测
3. AI 视觉分析图片中的场景元素
4. 提取各场景维度的检测值
5. 与世界观设定库中的场景定义进行比对
6. 生成场景一致性检测报告

**界面要求：**
- 检测报告以卡片形式展示，与人物检测报告并列
- 场景元素展示：每行一个维度，显示维度和检测值
- 设定值展示：在检测值旁边显示"设定：[值]"
- 一致/不一致标记：与第 77 章保持一致的颜色体系
- 图片场景标注：在图片上标注检测到的场景区域（天空、建筑、植被等）

#### 78.2.2 季节/天气不符报警

**功能描述：**
- 当检测到的季节特征与设定严重不一致时触发报警
- 当检测到的天气状况与设定矛盾时触发报警
- 报警等级：季节不符 = 严重（橙色），天气不符 = 警告（黄色）
- 报警信息包含：不符项、检测值、设定值、置信度
- 季节/天气不符报警独立于其他场景维度的比对

**操作流程：**
1. 检测发现季节或天气与设定不符
2. 系统自动触发报警通知
3. 报警显示在检测报告顶部
4. 报警列入质量控制中心的问题列表
5. 用户可查看具体不符内容并决定如何处理
6. 可点击"忽略"标记报警为已处理

**界面要求：**
- 季节不符报警：橙色 ⚠️ 徽章 + "季节不符"文字
- 天气不符报警：黄色 ⚠️ 徽章 + "天气矛盾"文字
- 报警详情弹窗：显示设定季节/天气 vs 检测季节/天气
- 报警列表中的条目：Panel 编号 + 场景名 + 报警类型 + 时间
- 处理按钮："忽略"、"查看图片"、"重新生成"

### 78.3 数据模型

| 字段 | 类型 | 说明 |
|------|------|------|
| scene_detection_id | UUID | 场景检测唯一标识 |
| panel_id | UUID | 关联 Panel ID |
| scene_asset_id | UUID | 关联场景资产 ID |
| detected_elements | JSON | 检测到的场景元素 |
| expected_elements | JSON | 期望的场景设定值 |
| comparison_results | JSON | 各维度比对结果 |
| alerts | JSON | 触发的报警列表 |
| created_at | DateTime | 检测时间 |

## 第79章 道具一致性检测

### 79.1 功能概述

道具一致性检测模块负责验证新生成图片中道具的外观与道具资产库中的设定是否一致，同时检测画格中是否出现了预期应该出现但实际缺失的道具。该模块确保关键道具在漫画各画面中的视觉连续性，避免漏画或外观突变的问题。

**输入：**
- 新生成的 Panel 图片
- 该 Panel 关联的道具列表（来自剧情拆解中的道具标注）

**输出：**
- 道具外观一致性检测结果
- 漏画道具检测结果
- 不一致/缺失报警

### 79.2 功能点

#### 79.2.1 道具外观与道具资产库对比

**功能描述：**
- AI 目标检测识别图片中出现的道具物体
- 将检测到的道具与道具资产库的设定外观进行比对
- 比对维度包括：道具类型、颜色、形状、尺寸比例、材质纹理
- 支持关键道具（剧情重要道具）的精细比对
- 比对结果按道具分组展示

**操作流程：**
1. 从剧情拆解数据中获取该 Panel 应出现的道具列表
2. 对图片执行道具目标检测
3. 识别出图片中实际出现的道具
4. 对每个识别的道具，与资产库中的设定比对
5. 生成道具比对结果
6. 不一致的道具标记显示

**界面要求：**
- 道具检测结果列表：每个道具一行
- 每行显示：道具名称 + 资产库参考图（缩略图）+ 检测结果图（裁剪区域）
- 一致标记：绿色 ✓
- 不一致标记：红色 ✗ + 差异描述（如"颜色：设定红色 → 检测蓝色"）
- 未在图片中找到的道具：灰色 ⬜ + "未检测到"
- 参考图对比：不一致的道具显示参考图与检测图的并列对比

#### 79.2.2 漏画道具检测

**功能描述：**
- 根据剧情拆解数据，确定该 Panel 预期应出现的道具列表
- 与目标检测结果进行交叉比对
- 预期出现但在图片中未检测到的道具标记为"漏画"
- 漏画检测结果按严重程度分级：
  - 关键道具漏画：严重（红色）
  - 普通道具漏画：警告（黄色）
  - 装饰性道具漏画：提示（蓝色）
- 漏画道具生成报警

**操作流程：**
1. 从剧情拆解中心获取该 Panel 的预期道具列表（含道具重要性等级）
2. 执行图片目标检测，获取实际出现道具列表
3. 计算预期道具与实际道具的差集
4. 对差集中的道具按重要性分级标记
5. 生成漏画检测报告
6. 触发漏画报警

**界面要求：**
- 漏画列表：红色/黄色/蓝色背景的卡片列表
- 每个漏画项显示：道具名称 + 重要性等级 + 参考图 + "预计位置"提示
- 关键道具漏画：大号红色报警徽章 + 闪烁边框
- "预计位置"：基于剧情上下文的文字描述（如"角色右手应持剑"）
- 一键跳转：点击漏画项跳转到生图中心重新生成
- 忽略按钮：确认该道具在此画面中确实不需要

### 79.3 数据模型

| 字段 | 类型 | 说明 |
|------|------|------|
| prop_detection_id | UUID | 道具检测唯一标识 |
| panel_id | UUID | 关联 Panel ID |
| expected_props | JSON | 预期道具列表 |
| detected_props | JSON | 检测到的道具列表 |
| mismatched_props | JSON | 外观不一致的道具列表 |
| missing_props | JSON | 漏画道具列表 |
| alerts | JSON | 触发报警列表 |
| created_at | DateTime | 检测时间 |

## 第80章 画风一致性检测

### 80.1 功能概述

画风一致性检测模块评估整部漫画的视觉风格统一性。系统分析每张图片的线稿风格、上色风格和光影风格特征，计算各 Panel 之间的风格相似度，发现风格跳变并报警。该模块在批量生成和不同批次的生成之间尤为重要，确保整部漫画读起来像出自同一画师之手。

**输入：**
- 项目内所有已生成的 Panel 图片（或指定批次）
- 参考风格模板图片（可选）

**输出：**
- 各 Panel 的风格特征向量
- Panel 间的风格相似度矩阵
- 风格一致性评分
- 风格跳变报警

### 80.2 功能点

#### 80.2.1 全漫画画风统一性检测

**功能描述：**
- 对项目内所有已生成的图片提取风格特征
- 风格特征包括三个维度：
  - 线稿风格：线条粗细、线条密度、线条干净度
  - 上色风格：饱和度分布、色相分布、上色方式（平涂/厚涂/赛璐珞）
  - 光影风格：高光强度、阴影锐利度、光源一致性
- 计算各 Panel 之间的风格相似度
- 生成整体风格一致性指数（0-100%）

**操作流程：**
1. 进入画风一致性检测页面
2. 选择检测范围（全部章节 / 指定章节 / 指定批次）
3. 点击"开始检测"
4. 系统对所有选中图片执行风格特征提取
5. 计算面板间两两风格相似度
6. 生成整体一致性评分和可视化报告

**界面要求：**
- 检测范围选择：下拉框 + 章节/批次多选
- 检测按钮：页面顶部"🔍 开始检测"蓝色主按钮
- 检测进度：显示"正在分析第 X/Y 张图片..."
- 评分展示：大号数字 + 圆形进度指示器
- 评分颜色：≥90% 绿色 / 70-89% 黄色 / <70% 红色

#### 80.2.2 线稿、上色、光影风格一致性评分

**功能描述：**
- 分别计算三个风格维度的独立评分
- 每个维度 1-10 分
- 提供每个维度的详细分析报告
- 各维度的评分加权计算综合得分

**评分维度权重：**

| 维度 | 权重 | 评分依据 |
|------|------|---------|
| 线稿风格一致性 | 35% | 线条粗细方差、线稿密度分布 |
| 上色风格一致性 | 40% | 色相分布对齐度、饱和度一致性 |

## 第81章 漏字检测

### 81.1 功能概述

漏字检测模块自动扫描生成图片中是否包含预期外的文字内容。在 AI 生图过程中，模型有时会在画面中错误地生成文字（如乱码、无意义字符、商标文字等），漏字检测模块能够高精度地检测出这类问题文字，确保漫画画面的纯净。

**输入：**
- 新生成的 Panel 图片

**输出：**
- 图片中是否存在预期外文字的判定
- 检测到的文字区域标注
- 文字内容识别结果

### 81.2 功能点

#### 81.2.1 检测图片中是否出现预期外的文字

**功能描述：**
- 利用场景文本检测算法扫描整张图片
- 检测图片中任意位置出现的文字区域
- 对检测到的文字区域用边界框标注
- 与 Panel 中已有的气泡文本区域进行比对
- 判定：气泡区域内的文字不计为"预期外"，非气泡区域的文字标记为"预期外"

**操作流程：**
1. 图片生成后自动触发漏字检测
2. 执行场景文本检测（EAST/DBnet 等算法）
3. 获取所有文字区域的坐标和置信度
4. 从 Panel 数据中获取已有气泡的坐标位置
5. 排除气泡区域内的文字
6. 将剩余的文字区域标记为"预期外文字"
7. 生成检测结果

**界面要求：**
- 检测结果概览：页面顶部的通过/不通过徽章
- 文字区域标注：在图片上用红色半透明矩形框标注预期外文字区域
- 标注框上显示置信度百分比
- 无预期外文字时显示绿色"✓ 未检测到预期外文字"
- 检测到文字时显示红色"⚠️ 检测到 X 处预期外文字"

#### 81.2.2 中/英/韩文检测

**功能描述：**
- 支持对检测到的文字进行语言识别
- 支持三种语言的检测和区分：中文、英文、韩文
- 对每种语言的文字分别标注语言标签
- 支持 Unicode 字符范围区分各语种
- 输出每种语言的出现数量和位置

**操作流程：**
1. 检测到文字区域后，对每个区域执行 OCR 识别
2. 对识别结果进行语言判定
3. 在文字区域标注框上添加语言标签
4. 报告中按语言分组展示检测到的文字
5. 可根据语言类型筛选显示

**界面要求：**
- 语言标签：在文字区域标注框的左上角显示
  - 中文：红色"中"标签
  - 英文：蓝色"EN"标签
  - 韩文：绿色"KR"标签
- 语言统计：报告中按语言分类统计文字数量
- 语言筛选器：可按语言类型筛选显示的文字区域
- 文字内容展示：鼠标悬停标注框时显示识别出的文字内容

## 第82章 OCR 检测

### 82.1 功能概述

OCR 检测模块对图片中的文字进行光学字符识别，将识别结果与预期文字内容进行比对验证。与漏字检测（检测是否有预期外文字）不同，OCR 检测侧重于验证预期内的文字（气泡中的对白、旁白等）是否正确渲染。当气泡文本在生图过程中被 AI 错误写入图片时，OCR 可辅助发现并修正。

**输入：**
- Panel 图片
- 预期文字内容（来自漫画文本中心）

**输出：**
- OCR 识别结果文本
- 识别结果与预期的比对报告
- 文字内容正确性判定

### 82.2 功能点

#### 82.2.1 对图片中的文字进行 OCR 识别

**功能描述：**
- 对 Panel 图片中所有文字区域执行高精度 OCR 识别
- 支持识别印刷体中文、英文、韩文、数字和标点
- 识别结果包含：识别文本、置信度、文字区域坐标
- 支持批量图片 OCR 检测
- 识别结果可导出

**操作流程：**
1. 进入 OCR 检测页面，选择一个或多个 Panel
2. 点击"执行 OCR 检测"
3. 系统对选中图片执行 OCR 识别
4. 识别进度实时显示
5. 完成后面板展示所有识别结果
6. 识别结果按 Panel 分组显示

**界面要求：**
- 识别结果视图：左栏为图片（文字区域标注），右栏为识别文本列表
- 文字区域标注：绿色边界框标注每个识别到的文字块
- 标注框编号与识别文本列表的行编号对应
- 每行识别结果显示：编号 + 识别文本 + 置信度（百分比）
- 置信度低于 70% 的识别结果标黄提醒
- 批量检测进度：进度条 + "已完成 X/Y 张"

#### 82.2.2 识别结果展示

**功能描述：**
- 以结构化列表展示 OCR 识别结果
- 每条结果包含：文字序号、文字内容、置信度、坐标位置
- 支持将识别结果与 Panel 关联的气泡文本进行对比
- 支持在图片上高亮显示选中的文字区域
- 支持复制识别文本

**操作流程：**
1. OCR 识别完成后，结果自动展示在结果面板
2. 默认按阅读顺序排列文字块
3. 点击结果条目，图片上对应文字区域高亮
4. 点击"复制"按钮复制该条识别文本
5. 切换 Tab 查看"识别结果"和"比对结果"
6. 导出识别结果（JSON / CSV）

**界面要求：**
- 结果列表：表格布局
  - 列：序号、识别文本、置信度（带颜色进度条）、坐标预览
- 置信度颜色：≥90% 绿色 / 70-89% 黄色 / <70% 红色
- 选中高亮：点击列表行，图片上对应的文字区域显示蓝色高亮框
- 复制按钮：每行右侧的"📋 复制"按钮
- 导出按钮：结果列表上方的"📥 导出识别结果"

#### 82.2.3 判断文字内容是否正确

**功能描述：**
- 将 OCR 识别结果与漫画文本中心中的预期文本进行比对
- 比对策略：逐条对比 OCR 结果与气泡文本
- 比对结果分为：
  - 完全匹配：✓ 绿色
  - 部分匹配（少量字符差异）：⚠️ 黄色
  - 不匹配：✗ 红色
- 差异高亮显示：在识别文本和预期文本中标注差异字符
- 自动计算文字正确率

**操作流程：**
1. OCR 识别完成后，自动进入比对模式
2. 系统从漫画文本中心获取该 Panel 的预期文字
3. 以气泡为单位进行 OCR 结果与预期文本的一对一比
4. 匹配度结果展示在"比对结果" Tab 中
5. 差异项用红色字体标注差异字符
6. 计算文字正确率 = 完全匹配数 / 总比较数 × 100%

**界面要求：**
- 比对结果 Tab：与识别结果 Tab 并列
- 比对列表：每行一个气泡的比对
  - 预期文本（绿色高亮区域）
  - 识别文本（灰色背景）
  - 匹配度（百分比 + 颜色）
  - 差异字符高亮标记（红色背景）
- 完全匹配行：显示绿色 ✓
- 不匹配行：显示红色 ✗ + 差异详情
- 总体正确率：页面顶部的环形进度图
- 一键跳转：点击不匹配行可跳转到漫画编辑器修正

### 82.3 数据模型

| panel_id | UUID | 关联 Panel ID |
| ocr_results | JSON | OCR 识别结果列表 |
| expected_texts | JSON | 预期文本列表 |
| comparison_results | JSON | 比对结果列表 |
| accuracy_rate | Float | 文字正确率 |
| created_at | DateTime | 检测时间 |

## 第83章 AI 质量评分

### 83.1 功能概述

AI 质量评分模块通过 AI 视觉评估模型，对生成的图片从构图、色彩、角色表现力、背景细节等多个维度进行综合评分。每个维度 1-10 分，系统综合计算总分后输出详细的评分报告。低于设定质量阈值的图片自动标记为"需重新生成"，为用户的图片选择提供客观参考依据。

**输入：**
- 生成的 Panel 图片

**输出：**
- 各维度评分（1-10 分）
- 综合评分
- 评分报告（含评分依据）
- 低于阈值的自动标记

### 83.2 功能点

#### 83.2.1 综合评分

**功能描述：**
- 从多个维度对图片进行 AI 质量评估
- 评估维度：
  - 构图：画面布局合理性、主体位置、黄金分割利用
  - 色彩：色彩搭配和谐度、饱和度适中性、色调统一性
  - 角色表现力：角色表情生动度、姿态自然度、角色与环境的互动
  - 背景细节：背景丰富度、透视正确性、细节完成度
  - 光影：光照合理性、阴影准确性、对比度
  - 清晰度：图片锐度、噪点水平、细节保留度
  - 吸引力：整体视觉吸引力和美感综合评分
- 每个维度独立评分（1-10 分，1 最低，10 最高）
- 综合评分 = 各维度加权平均

**操���流程：**
1. 图片生成后自动触发 AI 质量评分
2. 也可在质量控制中心手动触发评分
3. AI 视觉模型逐维度分析评分
4. 评分完成后自动生成评分报告
5. 评分展示在检测报告的质量评分区域
6. 低于阈值的图片自动标记

**界面要求：**
- 评分展示：雷达图 + 各维度分数条
- 雷达图：七边形，每个顶点代表一个维度
- 分数条：水平进度条，左端 1 右端 10
- 综合评分：大号数字展示在雷达图中央
- 评分颜色：≥8 绿色 / 6-7.9 黄色 / <6 红色
- 评分加载：评分中显示骨架屏动画

#### 83.2.2 每个维度 1-10 分

**功能描述：**
- 每个评估维度的细粒度评分（1-10 整数或小数）
- 每个维度的评分附带简要的文字说明
- 文字说明指出该维度的优缺点
- 低分项（< 6 分）自动标注改进建议
- 评分标准可配置（通过系统设置调整各维度权重）

**评分维度详解：**

| 维度 | 评分细项 | 满分 |

| 角色表现力 | 表情、姿势、角色与环境互动 | 10 |

3. 详细说明包含：得分、评分依据、改进建议

5. 评分结果与同章节其他 Panel 做横向对比

## 第84章 人工审核中心

### 84.1 功能概述

人工审核中心是质量控制流程中的人工干预环节，提供待审核 Panel 的集中处理队列。审核员可逐一对 Panel 执行通过、打回或需修改等审核操作，并填写审核备注。审核中心保留完整的审核历史记录，为质量追溯和管理决策提供依据。

**输入：**
- 所有已完成 AI 检测和质量评分的 Panel
- 审核员的操作指令

**输出：**
- 审核通过的 Panel（进入下一环节）
- 审核打回的 Panel（标记为需重新生成）
- 审核历史记录

### 84.2 功能点

#### 84.2.1 待审核 Panel 队列

**功能描述：**
- 集中展示所有待人工审核的 Panel
- 待审核 Panel 来自：AI 检测完成后未设定自动通过的、有检测报警的、AI 评分低于阈值的
- 队列支持多种排序和筛选：
  - 按章节顺序排序
  - 按质量评分排序（低分优先）
  - 按检测报警数量排序
  - 按 AI 判定结果筛选（通过/有条件通过/不通过）
- 队列显示每个 Panel 的核心信息：缩略图、章节编号、质量评分、检测报警数

**操作流程：**
1. 进入人工审核中心，默认展示所有待审核 Panel
2. 使用筛选器选择需要优先审核的 Panel（如"低分优先"）
3. 队列以卡片网格或列表形式展示
4. 每张卡片显示 Panel 缩略图 + 核心质量信息
5. 点击卡片进入该 Panel 的审核详情页
6. 支持逐张审核或批量审核

**界面要求：**
- 队列视图切换：网格视图 / 列表视图
- 网格视图：每行 4-5 个 Panel 卡片
- 卡片内容：缩略图 + 章节-Panel 编号 + 质量评分（颜色数字）+ 报警数量 + 审核状态
- 审核状态颜色：待审核（灰色）/ 已通过（绿色）/ 已打回（红色）
- 筛选栏：队列顶部的多条件筛选器（章节、评分范围、报警类型）
- 排序选择："低分优先"、"高报警优先"、"按章节顺序"
- 队列统计：顶部显示"待审核 X 个 / 已审核 Y 个"
- 空队列：全部审核完成时显示"🎉 所有 Panel 已审核完成"

#### 84.2.2 审核操作：通过/打回/需修改

**功能描述：**
- 审核员对 Panel 执行三种审核操作：
  - **通过**：Panel 质量合格，进入下一环节（漫画编辑器）
  - **打回**：Panel 质量不合格，标记为需重新生成
  - **需修改**：Panel 有小问题，通知生图中心修改特定部分
- 通过操作可选择是否同时选择当前候选图
- 打回操作需至少填写一个原因
- 需修改操作需指定修改内容和优先级

**操作流程：**

**通过：**
1. 审核员在审核详情页确认 Panel 质量
2. 点击"通过"按钮
3. 可选择是否同时选择当前候选图为最终图片
4. Panel 状态更新为"审核通过"
5. 自动进入下一流程（漫画编辑器）

**打回：**
1. 审核员判断 Panel 质量不合格
2. 点击"打回"按钮
3. 弹出打回原因选择面板（多选）：
   - 角色特征不一致
   - 场景/道具错误
   - 画风突变
   - 图片质量差（模糊/变形）
   - 构图不符合要求
   - 其他（自定义输入）
4. 确认后 Panel 标记为"需重新生成"
5. 自动进入重新生成队列

**需修改：**
1. 审核员认为 Panel 有小问题需要修改
2. 点击"需修改"按钮
3. 填写修改说明（指定修改内容和位置）
4. 选择修改优先级（高/中/低）
5. Panel 标记为"待修改"
6. 修改完成后重新提交审核

**界面要求：**
- 审核操作按钮组：审核详情页底部的三个大按钮
  - "✓ 通过"：绿色主按钮
  - "✗ 打回"：红色按钮
  - "🔧 需修改"：黄色按钮
- 通过确认：简单 toast 提示"已标记为通过"
- 打回弹窗：显示原因选项（多选复选框）+ 自定义输入框
- 需修改弹窗：修改说明输入框 + 优先级选择器
- 快捷操作：在队列卡片上直接提供"通过"和"打回"操作按钮（无需进入详情）
- 批量审核：多选 Panel 后统一操作（批量通过/批量打回）

#### 84.2.3 审核备注

**功能描述：**
- 每次审核操作可附加审核备注
- 备注为自由文本，长度不限
- 备注内容分两部分：预设原因 + 自定义说明
- 备注支持富文本格式（加粗、列表等）
- 备注记录到审核历史中，供后续追溯

**操作流程：**
1. 在审核操作弹窗中，填写审核备注
2. 如需额外说明，在自定义输入框中补充
3. 备注与审核操作一起提交保存
4. 审核历史中可查看每条备注
5. 备注支持后续编辑补充

**界面要求：**
- 备注输入框：审核操作弹窗中的多行文本框
- 预设原因：复选框列表，选中后自动填入备注输入框
- 自定义输入：输入框底部，标注"补充说明"
- 字数统计：输入框右下角显示当前字数
- 备注预览：在审核历史中以卡片形式展示备注内容
- 备注编辑：审核历史中的备注支持"编辑"操作

#### 84.2.4 审核历史记录

**功能描述：**
- 完整记录每次审核操作的所有信息
- 每条审核记录包含：审核时间、审核人、审核操作、审核备注
- 审核历史按时间倒序排列
- 支持按 Panel 查看审核历史
- 支持按审核人、审核操作、时间范围筛选

**操作流程：**
1. 在审核中心中切换到"审核历史" Tab
2. 默认展示最近的审核记录
3. 使用筛选器按条件过滤
4. 点击某条记录展开查看���节
5. 点击"查看 Panel"跳转到该 Panel 的详情页
6. 导出审核历史

**界面要求：**
- 审核历史列表：表格布局
  - 列：时间、审核人、Panel 编号、审核操作（通过/打回/修改）、备注摘要、详情按钮
- 审核操作列：颜色标签（通过=绿色/打回=红色/修改=黄色）
- 展开详情：点击行展开显示完整备注内容
- 跳转链接：Panel 编号列可点击跳转
- 筛选器：审核人下拉 + 操作类型下拉 + 时间范围选择器
- 导出按钮：列表上方的"📥 导出审核记录"按钮
- 统计信息：列表顶部显示"共 X 条审核记录"
