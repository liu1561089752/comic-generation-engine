# AI Webtoon Factory 开发路线图与里程碑计划

> 版本：v1.0

> 状态：草案
> 对应 PRD：第 125 章 开发路线图

---

## 1. 总体阶段划分

将整个项目分为 3 个阶段，从 MVP 到商业版本渐进演进：

| 阶段 | 时间跨度 | 核心目标 | 产出能力 |
|------|----------|----------|----------|
| **MVP 阶段** | 1-3 个月 | 可运行版本 | 一条完整的"短篇小说→Webtoon"制作管线，可产出 20-50 话的完整 Webtoon |
| **V2 阶段** | 4-6 个月 | 生产版本 | 多项目并行、批量生图、一致性检测，支持中长篇（50-200 话） |
| **V3 阶段** | 7-12 个月 | 商业版本 | 插件系统、多模型支持、商业级功能，面向个人和小型工作室发布 |

## 2. MVP 阶段（1-3 个月）

### 2.1 目标

实现完整的一条"短篇小说→Webtoon"制作管线，可产出 20-50 话的完整 Webtoon。

**核心原则：**
- 全链路打通优先，功能深度次之
- 手动+AI 混合模式（AI 不可用时可手动输入）
- 单用户模式，不涉及权限系统
- 以 SQLite 作为开发数据库，降低部署门槛

### 2.3 MVP 里程碑

| 里程碑 | 时间节点 | 交付物 | 验收标准 |
|--------|----------|--------|----------|
| **M1** | 第 2 周末 | 项目骨架 | 前后端连通，可登录注册，Dashboard 可访问 |
| **M2** | 第 4 周末 | 小说管理 | 可上传 TXT/DOCX/MD 小说，自动拆分章节，阅读器可用 |
| **M3** | 第 6 周末 | 角色+世界观 | 可创建角色和世界观，人物关系图可展示 |
| **M4** | 第 8 周末 | 剧情分析+分镜 | 可进行 AI 剧情分析，Scene/Panel 管理可用 |
| **M5** | 第 10 周末 | Prompt+生图 | 可由 Prompt 生成图片，候选图可选择 |
| **M6** | 第 12 周末 | MVP 发布 | 可产出完整 Webtoon（长图/PNG） |

### 2.4 MVP 验收标准

- [ ] 可以上传一部短篇小说（1-5 万字），支持 TXT/DOCX/MD 格式
- [ ] 可设置世界观和角色（至少 3 个角色，含外貌、性格等基本信息）
- [ ] 可完成 AI 剧情分析，提取 Scene 结构
- [ ] 可完成语义切句，将 Scene 拆分为 Panel
- [ ] 可生成 Prompt 并调用 AI 生图接口
- [ ] 可查看候选图（至少 4 张），可选择满意的图片
- [ ] 可编辑漫画（调整气泡位置、选择版式模板）
- [ ] 可导出为长图/PNG，图片分辨率 ≥ 1080×1440
- [ ] 全程无数据丢失，支持保存/恢复项目进度
- [ ] 核心页面加载时间 < 3 秒

## 6. 风险管理

### 6.1 风险矩阵

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| **AI 生图质量不稳定**（手指变形、面部扭曲、构图不合理） | 高 | 高 | 多候选机制（4-8 张/Panel）+ 人工选择 + 质量评分 Agent 自动筛选 |
| **角色一致性达不到要求**（同一角色在不同画格中相貌变化） | 中 | 高 | 参考图+六视图+特征 Checklist + 一致性检查 Agent 自动检测 |
| **API 调用成本过高**（大量生图和 LLM 调用导致费用超预算） | 中 | 中 | 支持多种模型切换，选择性价比方案；本地部署开源模型（SDXL/DeepSeek）降本 |
| **批量生图性能瓶颈**（大量 Panel 同时处理导致排队过长） | 中 | 中 | Celery 任务队列+优先级管理+并发控制；支持动态扩容 Worker |
| **前端编辑性能问题**（Canvas 渲染大量高分辨率图片卡顿） | 中 | 中 | 虚拟滚动+图片懒加载+缩略图分级；Web Worker 处理图片解码 |
| **后端性能瓶颈**（数据库查询慢、API 响应时间长） | 低 | 中 | 任务队列+Redis 缓存+数据库索引优化；读写分离（V3） |
| **开发进度延迟**（技术难度过高或需求变更导致延期） | 中 | 中 | 每个 Sprint 预留 20% 缓冲时间；MVP 阶段严格 scope 控制 |
| **AI 模型接口变更**（第三方 API 不兼容或废弃） | 低 | 高 | 适配器模式隔离外部依赖；支持多模型切换，不绑定单一供应商 |
| **数据丢失**（未保存、数据库损坏、文件系统故障） | 低 | 高 | 自动保存（每 30 秒）+ 版本管理 + 定期备份（V3 完整方案） |

### 6.2 风险应对策略优先级

1. **高概率+高影响** → 必须内置缓解措施（如多候选机制、人工审核）
2. **中概率+高影响** → 设计防御性架构（如适配器模式、角色一致性检测）
3. **低概率+高影响** → 建立恢复机制（如数据备份、导出导入）
4. **中概率+中影响** → 预留优化空间（如缓存、队列、性能监控）

### 7.3 已知技术债务条目（MVP 阶段接受，后续偿还）

| 债务项 | 描述 | 计划偿还时机 |
|--------|------|-------------|
| SQLite 用于开发/单机部署 | 缺乏并发能力和 JSONB 支持 | V2 强制 PostgreSQL |
| 无 Celery 任务队列 | MVP 使用同步模式或 Eager 模式 | Sprint 7 引入 |
| 人物关系图前端渲染优化 | 大量节点时性能下降 | V2 优化 |
| 图片存储使用本地文件系统 | 缺乏分布式能力和灾备 | V2 引入 MinIO |
| 无 TypeScript 严格模式 | 部分模块类型宽松 | V2 统一启用 |
| 字体/特效文字仅支持基础样式 | 缺乏高级排版能力 | Sprint 11 |
| 无自动化测试 | MVP 以手动测试为主 | Sprint 7 开始补充 |
