## 1. 项目身份

| 属性 | 内容 |
|------|------|
| **项目名称** | AI Webtoon Factory（AI韩漫工厂） |
| **项目口号** | 让一个人拥有一个韩漫工作室的生产力 |
| **项目定位** | 从小说导入到 Webtoon 导出的工业化 AI 生产管线 |
| **核心差异** | 不是 AI 生图工具，而是 AI 制片系统 |
| **目标用户** | 个人漫画创作者、小型漫画工作室、AI 生图运营人员 |

### 1.1 项目背景

传统韩漫制作流程涉及编剧、分镜师、主笔、上色师、后期编辑等多角色协作，制作周期长、人力成本高。AI Webtoon Factory 旨在将这些角色的工作流全面 AI 化，让一个人即可完成从原始文本到可发布 Webtoon 的全部工序。

### 1.2 系统边界

**覆盖范围：**
- TXT/DOCX/Markdown 小说导入到 Webtoon 导出的全流程
- 1:1.34（1080×1440+）标准 Webtoon 竖屏比例
- PNG/JPG/PSD/ZIP/长图等多种导出格式
- 可选插件扩展机制

**不覆盖范围：**
- AI 写小说（需外部导入文本源）
- 在线发布/分发平台
- 多人实时协同编辑（V1 为单用户模式）
- 漫画印刷排版

## 2. 核心产品哲学

系统设计的五大核心哲学，所有架构决策和产品功能必须遵循：

### 2.1 结构化优先

> 所有中间产物以结构化 JSON 存储，而非自然语言文本。

- Novel → Chapter → Scene → Panel → Shot → Bubble → Prompt → Image 每层数据严格建模
- 确保数据可解析、可追溯、可增量更新
- AI Agent 的输入输出均为 JSON，避免自然语言歧义

### 2.2 可追溯

> 每张图片可追溯到原文段落。

- 每张生成图片持有 `panel_id → scene_id → chapter_id → novel_id` 完整链路
- 支持从成品图逆向追溯到原始文本和决策过程
- 数据变更记录完整审计日志

### 2.3 可迭代

> 任意环节可独立重做。

- 修改上游数据（如 Scene 文本）后，下游数据标记为 `stale`，而非自动删除
- 支持单 Panel 重新生成，不影响管线中其他数据
- Prompt、Image、气泡等关键资源支持版本管理

### 2.4 工业化

> 像工厂流水线一样可重复、可控制。

- 10 个 AI Agent 组成标准化生产管线
- 每个 Agent 职责单一、输入输出明确、可独立替换
- 支持自定义工作流编排（跳过/替换 Agent）

### 2.5 模块化

> 每个组件独立可替换。

- AI 模型通过适配器模式解耦，不绑定任何特定模型
- 前端模块与后端服务一一对应，支持独立开发
- 插件系统支持第三方功能扩展

## 4. 10 层 Prompt 结构

系统使用独特的 10 层结构化 Prompt 机制，确保生图质量和一致性：

| 层号 | 名称 | 内容来源 | 示例 |
|------|------|----------|------|
| 第 1 层 | 角色描述 | 人物 IP 中心 | 黑发棕眼年轻男性，穿黑色皮夹克 |
| 第 2 层 | 环境场景 | 世界观资产库 | 温馨咖啡馆，暖色灯光，窗外下雨 |
| 第 3 层 | 动作姿态 | 分镜数据 | 坐姿拿咖啡杯，向右警惕地看 |
| 第 4 层 | 情绪表情 | 分镜数据 | 紧张但期待，微皱眉，肩膀紧绷 |
| 第 5 层 | 镜头语言 | 镜头规划 | 中景，平视，固定镜头 |
| 第 6 层 | 光影照明 | 自动推导 | 顶灯暖光+窗边冷蓝辅光 |
| 第 7 层 | 构图布局 | 构图规划 | 三分法，主体在左 1/3，背景虚化 |
| 第 8 层 | 画风风格 | 风格模板 | Webtoon 风格，半写实，赛璐璐上色 |
| 第 9 层 | 气泡预留 | 气泡规划 | 右侧空白气泡，指向左侧 |
| 第 10 层 | 负向提示 | 系统预设+自定义 | nsfw, low quality, bad anatomy |

## 5. 关键架构决策（ADR 摘要）

### ADR-001：使用 PostgreSQL 而非 MongoDB

- **决策**：采用 PostgreSQL 作为主数据库
- **理由**：数据关系复杂（树形层级 + 多对多关系），PostgreSQL 的 JSONB 支持结构化数据存储，GIN 索引支持全文搜索，事务完整性保障数据一致性
- **替代方案**：开发环境使用 SQLite，通过 SQLAlchemy 方言切换

### ADR-002：Panel 作为最小操作单元

- **决策**：Panel（画格）是系统中最核心、最小的独立操作单元
- **理由**：Panel 是漫画的基本视觉单位，所有下游操作（Shot、Bubble、Prompt、Image）均依附于 Panel。以 Panel 为单位进行状态管理、版本控制和重新生成，粒度最合适

### ADR-003：Prompt 最后生成

- **决策**：Prompt 在所有上游数据（角色、场景、动作、镜头、画风）准备就绪后才生成
- **理由**：Prompt 是下游生图模型的数据聚合结果，而非独立的创意环节。延迟生成确保每层数据最新，避免重复劳动

### ADR-004：10 层 Prompt 结构

- **决策**：Prompt 采用 10 层分离结构，而非传统单一段落式 Prompt
- **理由**：分离结构支持逐层溯源、逐层替换、逐层消融实验；便于兼容不同生图模型对 Prompt 格式的差异化要求

### ADR-005：适配器模式解耦 AI 模型

- **决策**：通过适配器模式抽象 LLM 和生图模型
- **理由**：不绑定任何特定 AI 模型/服务，用户可自由切换底层模型（GPT-4 ↔ DeepSeek、SDXL ↔ Midjourney），降低供应商锁定风险

## 6. 十诫（不可触碰的原则）

以下十条为项目的根本性原则，任何代码提交不得违反：

### 诫命一：所有 AI Agent 输入输出必须是结构化 JSON
- AI Agent 之间传递的数据必须使用预定义的 JSON Schema
- 禁止使用自然语言文本作为 Agent 间通信格式
- 违反后果：数据链路断裂，无法追溯

### 诫命二：Panel 必须有原文追溯 ID
- 每个 Panel 必须持有 `paragraph_ref` 字段，指向原始文本段落
- 确保从成品图片到原文的可逆向追溯
- 违反后果：失去"可追溯"的核心产品价值

### 诫命三：角色设定不能写死在 Prompt 里
- 角色外观、服装等设定必须存储在人物 IP 中心，通过引用注入 Prompt
- 禁止在 Prompt 模板中硬编码角色特征
- 违反后果：角色一致性维护成本极高

### 诫命四：每张图必须保留完整生成参数
- Image 记录必须包含 Prompt 全文、负向 Prompt、模型名称、Seed、CFG Scale、Steps、Width、Height
- 确保结果可复现、可审计
- 违反后果：失去可复现性

### 诫命五：任何数据变更必须有审计日志
- 所有 CRUD 操作记录操作人、操作时间、变更前后数据快照
- 使用 `SystemLog` 表记录
- 违反后果：无法追溯问题来源

### 诫命六：AI Agent 必须可独立重跑
- 每个 Agent 必须是幂等的，重复执行应得到相同或等价结果
- Agent 不应依赖外部副作用状态
- 违反后果：管线调试困难

### 诫命七：数据库永远不存储图片文件
- 数据库只存储图片的元数据和文件路径
- 图片文件存储在对象存储（MinIO）或本地文件系统
- 违反后果：数据库体积膨胀，备份困难

### 诫命八：前端永不接触 API Key
- API Key 仅在后端使用，前端通过后端接口间接调用 AI 服务
- 前端配置文件禁止包含任何敏感凭据
- 违反后果：API Key 泄露风险

### 诫命九：任何时候都可以单 Panel 重新生成
- 系统必须支持对任意单个 Panel 独立发起重新生成
- 重新生成不应对管线中其他 Panel 产生副作用
- 违反后果：用户编辑体验差

### 诫命十：所有 API 必须向后兼容
- 次版本和补丁版本升级不得破坏已有 API 的请求/响应格式
- 新增参数必须为可选，且带默认值
- 违反后果：前端和集成方频繁适配

## 7. 10 个 AI Agent 管线

| # | Agent ID | 名称 | 职责 | LLM 依赖 |
|---|----------|------|------|----------|
| ① | `text_cleaner` | 文本清洗 Agent | 标准化去噪，格式统一 | 每章一次 |
| ② | `story_analyzer` | 剧情分析 Agent | 提取 Scene 结构 | 每章一次 |
| ③ | `semantic_splitter` | 语义切句 Agent | Scene → Panel 拆分 | 每个 Scene 一次 |
| ④ | `storyboard_planner` | 分镜规划 Agent | 视觉分镜方案 | 每 5-10 Panel 一次 |
| ⑤ | `camera_planner` | 镜头规划 Agent | 镜头类型/景别/运镜 | 每 5-10 Panel 一次 |
| ⑥ | `layout_planner` | 版式规划 Agent | Panel → 页面布局 | 每 30-50 Panel 一次 |
| ⑦ | `bubble_planner` | 气泡规划 Agent | 文本 → 气泡列表 | 每 10-20 Panel 一次 |
| ⑧ | `prompt_generator` | Prompt 生成 Agent | 10 层 Prompt 组装 | 无需 LLM |
| ⑨ | `consistency_checker` | 一致性检查 Agent | 角色特征逐维度比对 | 无需 LLM |
| ⑩ | `quality_scorer` | 质量评分 Agent | 多维度量化评分 | 无需 LLM |
